# Codex開発引き継ぎ書：どうぶつベースボール

## 1. 目的
既存の野球ゲームプロジェクトに、かわいい動物キャラクターを組み込む。
まず既存リポジトリを調査し、現在の構成や動作を壊さずに実装計画を立てる。調査前に大規模な書き換えをしない。

## 2. このチャットで作成した試作品
- ファイル名：`baseball_chibi_characters.html`
- 内容：Three.jsを使った単一HTMLの3Dキャラクターギャラリー
- キャラクター：柴犬、トラ、猫、ウサギ、クマ、たれ耳ウサギ、人間、野球帽の宇宙人（計8体）
- 基本図形を組み合わせてキャラクターを生成。外部の3Dモデルファイルは使用していない。
- 大きな目、ハイライト、ピンクの頬、腕、バットを追加した試作品。
- OrbitControlsによる回転・ズーム、簡単な浮遊・耳や尻尾の揺れ、GLB一括出力を含む。
- Three.jsはCDNのimport map経由で読み込む。
- このHTMLは独立した試作品であり、既存ゲームに統合済みではない。まず実ファイルを確認してから扱うこと。

## 3. キャラクターのデザイン方針
- 野球ゲーム用のマスコットキャラクター。
- 人間と宇宙人以外は「とにかくかわいく」。
- 大きく丸いキラキラした目、柔らかい丸いシルエット、ほっぺの赤み、ぬいぐるみのような印象。
- 全キャラクターに腕とバットを持たせる。
- 現在の試作品の腕・バットは簡易表現。ゲームに組み込む際は、必要に応じて手がバットを握って見えるポーズに改善する。
- 今後はユニフォーム、チームカラー、打撃・投球・守備・走塁のモーションも検討する。

## 4. 技術方針
- 既存プロジェクトの技術スタックを最初に調査する。
- 既存ゲームがThree.jsを使っているか、2Dゲームか、フレームワークやビルド環境、起動・テスト方法を確認する。
- 既存構成に合わせて統合方法を決める。Three.jsを無条件に追加したり、既存システムを置き換えたりしない。
- 可能な限り小さく段階的に変更し、各段階で動作確認する。
- 既存機能を壊さないことを優先する。
- Gitの作業ブランチを使い、作業開始前の状態を保全する。
- APIキー、パスワード、秘密情報をコードやコミットに含めない。

## 5. Codexへの最初の指示
まずGitHubリポジトリ全体を調査し、コードを変更する前に以下を報告してください。

1. 使用技術、プロジェクト構成、起動方法、テスト方法
2. ゲームの現在の画面・機能と、キャラクター表示に関係するファイル
3. 3Dキャラクターを統合する場合の最小変更案
4. 今のプロジェクトでThree.jsを使うのが適切かどうか
5. 統合時のリスク、既存機能への影響、必要な素材や追加作業
6. 最初の小さな実装ステップと、その確認方法

調査後、実装方針を提示し、既存のゲームの仕組みを尊重して段階的に進めてください。最初から全体を作り直さないでください。

## 6. 実装の優先順位（提案）
1. 既存ゲームの構成と現状を把握する
2. 8体のうち1体を、ゲーム内のテスト画面やキャラクター選択画面に表示する
3. 回転・ズームや操作感、スマホ表示、読み込み性能を確認する
4. キャラクターの見た目を調整する（手とバットの握り、目、体型、色）
5. 必要なアニメーションを追加する
6. キャラクター選択・チーム編成など、既存ゲームの仕様に合わせて拡張する
7. 打撃・投球・守備などのゲーム内モーションを段階的に実装する
8. PC・スマホでテストし、既存機能の回帰テストを行う

## 7. 注意
- これは開発開始のための引き継ぎ書であり、既存リポジトリの内容をまだ確認していない。
- HTML試作品を本番コードにそのまま貼り付けるのではなく、既存の構成に合う形で再利用する。
- まず調査・計画を行い、確認可能な単位で実装する。
